## Usage Examples

### Success Response
```typescript
return ApiResponse.ok(data, 'USER.USER_CREATED_SUCCESS', { requestId, event });
```

### Error Response
```typescript
return ApiResponse.notFound('USER.USER_NOT_FOUND', { requestId, event }, { code: 'USER_NOT_FOUND' });
```

### Common Validation Error
```typescript
return ApiResponse.unprocessableEntity('COMMON.VALIDATION_ERROR', { requestId, event }, {
  code: 'VALIDATION_ERROR',
  details: errors
});
```

## Naming Patterns

| Pattern | Example |
|---------|---------|
| Success | `{MODULE}.{ENTITY}_{ACTION}_SUCCESS` |
| Not Found | `{MODULE}.{ENTITY}_NOT_FOUND` |
| Already Exists | `{MODULE}.{ENTITY}_ALREADY_EXISTS` |
| Invalid Field | `{MODULE}.{FIELD}_INVALID` |
| Status Info | `{MODULE}.{DESCRIPTIVE_NAME}` |

## Quick Tips

✅ Use your service module for service-specific messages  
✅ Use `COMMON.*` for shared/generic errors  
✅ Always use SCREAMING_SNAKE_CASE  
✅ Keep message codes descriptive and consistent  
✅ Include severity in CDN JSON (`SUCCESS`, `INFO`, `WARNING`, `ERROR`)
